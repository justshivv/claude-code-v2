# SC95F8523 Version of the 12 V 20 W Solar Street Light

Yes, the SinOne SC95F8523 can control both the LED driver and the MPPT
charger. The power stage in `DESIGN.md` stays mostly the same, but the
control method changes because this chip has none of the analog blocks
the PIC16F1769 design relied on.

The schematic for this version is in `schematic/` (four sheets, `schematic.pdf`) and as a
KiCad 7 project in `kicad/`.

Chip facts below are from the SC95F8523/8522/8521 datasheet V0.3
(SinOne, Chinese edition). Check them against the latest revision from
socmcu.com before layout. Numbers marked "estimate" come from `calc.py`
(output in `calc_output.txt`, section "SC95F8523 VARIANT").

## 1. What the chip has, and what that means

| SC95F8523 resource (datasheet) | Effect on the design |
|---|---|
| 1T 8051, 32 MHz, 16×16 hardware multiplier/divider, 32 KB flash, 4 KB SRAM | Enough for a firmware PI loop at 10 kHz plus MPPT, schedule and SOC |
| 8 × 16-bit PWM, clock fixed at 32 MHz (÷1/2/4/8) | At 100 kHz: 320 counts per period |
| **One period register shared by all 8 PWM channels** | Charger and LED driver must run at the same frequency. Both go to 100 kHz |
| Independent or complementary mode (4 pairs: 0/1, 2/3, 4/5, 6/7), mode set for all channels together | Use complementary mode. Pair 0/1 drives the charger half-bridge; PWM2 drives the boost (PWM3 left off, or used for a synchronous boost) |
| Dead time = 4 × n / 32 MHz, so 125 ns steps, one setting for all pairs | Minimum non-zero dead time is 125 ns. Put a Schottky across the charger's low-side FET to carry current during it |
| One fault input FLT (P0.4), active level, latch or auto-resume, 0/1/4/16 µs filter; on a fault PWM stops and outputs go **high impedance** | All hardware faults wired-OR into FLT. Pull-down resistors on every gate-driver input so a high-Z PWM pin means FET off |
| 12-bit ADC, 11 channels, 1 MHz, about 2 µs per conversion, internal 2.048 V reference (2.028–2.068 V) | Better ADC than the PIC (12-bit vs 10-bit). Use the 2.048 V reference |
| **No analog comparator, no op-amp, no DAC** | Add a quad comparator for protection and two current-sense amplifiers. The LED current loop moves into firmware |
| About 4.5 mA at 32 MHz, 5 V | Similar control power to the PIC |
| HRC 32 MHz ±1 % (−20 to 85 °C); can be calibrated from a 32.768 kHz crystal | Fit the crystal: accurate night timing and a steadier switching frequency |

## 2. Changes from the PIC16F1769 design

| Item | PIC16F1769 design | SC95F8523 design |
|---|---|---|
| LED current loop | Hardware peak current mode (comparator + slope ramp + COG) | Firmware PI loop at 10 kHz, writing PWM2 duty |
| LED current sense amp | On-chip op-amp | INA181A1 (gain 20), low side |
| Charge current sense amp | INA181, REF biased 0.3 V | INA181A3 (gain 100), REF to GND: 1.16 V at 5.8 A, 60 mV at 0.3 A |
| Brightness reference | On-chip DAC | Number in firmware (no DAC needed) |
| Over-current, OVP | On-chip comparators → COG shutdown | LM2901 quad comparator → FLT pin |
| Boost frequency | 200 kHz | 100 kHz (shared PWM period) |
| Boost inductor L1 | 68 µH | 100 µH, Isat ≥ 3.5 A, DCR ≤ 40 mΩ |
| Boost switch sense | 50 mΩ (in the control loop) | 33 mΩ (protection only) |
| Charger dead time | about 50 ns | 125 ns minimum, Schottky D2 across Q4 now required |
| Charger control | Firmware duty, P&O | Same |

Everything else in `DESIGN.md` (LEDs, battery, panel, charger FETs and
inductor, ideal diode, gate drivers, battery protection, layout) carries
over unchanged.

## 3. How the LED driver works without analog peripherals

The boost runs in voltage mode, controlled by firmware:

1. A timer interrupt at 10 kHz reads LED current (INA181 → ADC), runs a PI controller using the hardware multiplier, and produces a duty value with fractional bits.
2. One PWM count at 100 kHz moves the output by about 314 mV, which is about 52 mA of LED current (12-LED string, about 6 Ω dynamic resistance). That is too coarse on its own.
3. The PWM overflow interrupt (100 kHz) does sigma-delta dithering: each period it adds the fractional part to an accumulator and writes either N or N+1 counts. With 4 fractional bits the effective step is about 3.3 mA; with 6 bits about 0.8 mA.
4. The dither pattern repeats at 6.25 kHz or faster. The output LC filter (100 µH with 18.8 µF, double pole about 1.3 kHz) smooths it, so the LEDs see nearly DC.
5. Crossover is set to 100–200 Hz, well below the LC double pole and the right-half-plane zero (about 10 kHz at 11.2 V with 100 µH). Brightness changes are ramped over 2 s anyway, so a slow loop is fine.
6. Each loop pass also clamps the duty to D_max = 1 − Vbat / 45 V so the boost cannot push the output far past the LED voltage, even before the OVP comparator trips.

Write both duty bytes right after the PWM overflow interrupt so the
period-end reload never picks up half a value.

CPU load (estimate, measure it with a GPIO toggle on a scope): the
100 kHz dither ISR takes about 30–50 of the 320 CPU cycles per period
(10–15 %), and the 10 kHz PI loop with ADC read about 5–8 %. The rest
is free for MPPT, scheduling and SOC.

If firmware-only control turns out too slow or noisy on the bench, the
fallback is an external analog loop: a small op-amp error amplifier with
a filtered-PWM reference driving the boost duty. That costs one op-amp
and does not change the power stage.

## 4. Protection with one FLT pin

LM2901 quad open-collector comparator. All four outputs wired-OR to FLT
(P0.4) with a 4.7 kΩ pull-up to 5 V. FLT set active low, latched mode,
1 µs filter. Thresholds come from dividers on the 5 V rail.

| Comparator | Input | Trip point |
|---|---|---|
| A | Boost switch current, 33 mΩ in Q1 source, 100 Ω / 1 nF filter | 43k / 1.0k from 5 V → 0.114 V = 3.4 A |
| B | LED output voltage, R5/R6 430k / 20k (also the ADC reading) | 16k / 10k → 1.92 V = 43.3 V |
| C | Charger current, U5 INA181A3 output | 26k / 10k → 1.39 V = 6.9 A |
| D | Battery voltage, R3/R4 91k / 10k | 23.7k / 10k → 1.48 V = 15.0 V |

A fault stops all PWM outputs at once. That is acceptable here because
the charger only runs by day and the LED driver only by night, so one
shared fault input never shuts down a converter that should keep going.
Firmware reads the ADC to find which fault fired, logs it, clears
FLTSTA1 after 1 s and retries, up to 5 times.

Because the PWM pins go high impedance on a fault, fit 10 kΩ pull-downs
on the UCC27211 HI and LI inputs and on the boost driver input.

| 25 | P0.3 / PWM3 | Boost synchronous FET (optional, see section 6); otherwise unused |

| 18 | P2.2 / AIN0 | Panel voltage divider |
| 17 | P2.3 / AIN1 | Battery voltage divider |
| 16 | P2.4 / AIN2 | Charger current (INA181 #1) |
| 15 | P2.5 / AIN3 | LED current (INA181 #2) |
| 14 | P2.6 / AIN4 | LED voltage divider |
| 13 | P2.7 / AIN5 | Battery NTC |
| 12 | P1.7 / AIN6 | LED board NTC |
| 11 | P1.6 / AIN7 | 10 V gate-drive rail monitor |
| 10 | P1.5 | LED disconnect FET Q2 gate |
| 9 | P1.4 | PIR / motion sensor input (optional) |
| 23 | P0.5 | Enable for the 10 V gate-drive LDO |

inputs and those PWM channels stay off.

## 6. Efficiency (estimates)

| Path | Asynchronous boost (PWM2 + Schottky) | Synchronous boost (PWM2/PWM3 pair) |
|---|---|---|
| Battery → LED, 11.2 / 12.8 / 14.4 V | 96.1 / 96.4 / 96.6 % | 97.0 / 97.3 / 97.5 % |
| Battery → LED at 50 % / 30 % brightness | 95.8 / 94.7 % | 96.6 / 95.3 % |
| Panel → battery, 80 W | 98.4 % | 98.4 % |
| Panel → LED including battery cycle | 90.1 % | 91.0 % |

The LED driver comes out slightly better than the PIC version because it
switches at 100 kHz instead of 200 kHz, which halves switching and gate
losses. The cost is a larger inductor (100 µH instead of 68 µH).

The SC95F8523 makes the synchronous boost easy: complementary mode is
already on for the charger, so PWM2/PWM3 come as a pair with dead time.
Drive the top FET (in place of D1, 60 V, ≤ 14 mΩ) through a second
UCC27211 and keep D1 as a small Schottky in parallel for the 125 ns dead
time. Do this if the 91 % has to hold end to end.

## 7. Extra parts compared with the PIC design

| Part | Qty | Purpose |
|---|---|---|
| INA181A1 | 1 | LED current sense (U6) |
| INA181A3 | 1 | Charge current sense (U5), replaces the gain-50 part |
| LM2901 quad comparator | 1 | Hardware fault detection into FLT |
| 32.768 kHz crystal + 2 caps | 1 | Night timing, HRC calibration |
| 10 kΩ pull-downs | 3–4 | Gate-driver inputs stay low when PWM goes high-Z |
| Schottky D2 across Q4 | 1 | Now required (125 ns dead time) |
| UCC27211 + FET | 1 each, optional | Synchronous boost |

Part choices made while drawing the KiCad schematic (they apply to this version):

| Function | Part | Why |
|---|---|---|
| Boost gate driver | UCC27511 (SOT-23-6) instead of UCC27517 | Same family, split outputs (separate turn-on and turn-off resistors), in the KiCad library |
| 10 V gate-drive rail | LT3010 (80 V in, 50 mA, 30 µA, shutdown pin), 169k / 24.9k → 9.93 V | P0.5 can switch it off when neither converter runs |
| 5 V logic rail | LM2936-5.0 (40 V in, 50 mA, about 15 µA) | Always on for the SC95F8523 |
| Bootstrap capacitor | 100 nF | UCC27211 datasheet gives 22–100 nF as the typical range |
| Panel TVS | SMBJ28CA (bidirectional) | Also takes reverse surges on the panel cable |

## 8. Things to verify on the bench

1. That PWM2 runs alone with ENPWM3 = 0 while the chip is in complementary mode, and that disabling PWM1 alone gives a clean asynchronous charger.
2. FLT response time from comparator edge to PWM pins going high-Z.
3. LED current ripple from the dither, measured with a current probe. Aim for under 5 % peak to peak.
4. PI loop step response to a brightness change and to a battery voltage step, at 11.2, 12.8 and 14.4 V.
5. CPU load of the two interrupts.
6. Efficiency, using the procedure in `DESIGN.md` section 13, with the SC95F8523, INA181s and LM2901 supply current counted in the input.
