# SC95F8523 Version of the 12 V 20 W Solar Street Light

Yes, the SinOne SC95F8523 can control both the LED driver and the MPPT
charger. The power stage in `DESIGN.md` stays mostly the same, but the
control method changes because this chip has none of the analog blocks
the PIC16F1769 design relied on.

The schematic for this version is the KiCad 7 project in `kicad/` (PDF export:
`kicad/solar_light_schematic.pdf`, PNG renders in `schematic/`). It uses an IR2104
half-bridge driver for the charger and an L78L05 for the 5 V rail.

Chip facts below are from the SC95F8523/8522/8521 datasheet V0.3
(SinOne, Chinese edition). Check them against the latest revision from
socmcu.com before layout. Numbers marked "estimate" come from `calc.py`
(output in `calc_output.txt`, section "SC95F8523 VERSION").

## 1. What the chip has, and what that means

| SC95F8523 resource (datasheet) | Effect on the design |
|---|---|
| 1T 8051, 32 MHz, 16×16 hardware multiplier/divider, 32 KB flash, 4 KB SRAM | Enough for a firmware PI loop at 10 kHz plus MPPT, schedule and SOC |
| 8 × 16-bit PWM, clock fixed at 32 MHz (÷1/2/4/8) | At 100 kHz: 320 counts per period |
| **One period register shared by all 8 PWM channels** | Charger and LED driver must run at the same frequency. Both go to 100 kHz |
| Independent or complementary mode (4 pairs: 0/1, 2/3, 4/5, 6/7), mode set for all channels together | Use independent mode. PWM0 drives the IR2104 IN pin, PWM2 drives the boost. The IR2104 makes its own dead time, so the MCU's complementary pairs and dead-time register are not used |
| One fault input FLT (P0.4), active level, latch or auto-resume, 0/1/4/16 µs filter; on a fault PWM stops and outputs go **high impedance** | All hardware faults wired-OR into FLT. Pull-down resistors on every gate-driver input so a high-Z PWM pin means FET off |
| 12-bit ADC, 11 channels, 1 MHz, about 2 µs per conversion, internal 2.048 V reference (2.028–2.068 V) | Better ADC than the PIC (12-bit vs 10-bit). Use the 2.048 V reference |
| **No analog comparator, no op-amp, no DAC** | Add a quad comparator for protection and two current-sense amplifiers. The LED current loop moves into firmware |
| About 4.5 mA at 32 MHz, 5 V | Similar control power to the PIC |
| HRC 32 MHz ±1 % (−20 to 85 °C); can be calibrated from a 32.768 kHz crystal | Fit the crystal: accurate night timing and a steadier switching frequency |

## 2. Changes from the PIC16F1769 design

| Item | PIC16F1769 design | SC95F8523 design |
|---|---|---|
| LED current loop | Hardware peak current mode (comparator + slope ramp + COG) | Firmware PI loop at 10 kHz, writing PWM2 duty |
| LED current sense amp | On-chip op-amp | INA181A1 (gain 20), low side |
| Charge current sense amp | INA181, REF biased 0.3 V | INA181A3 (gain 100), REF to GND: 1.16 V at 5.8 A, 60 mV at 0.3 A |
| Brightness reference | On-chip DAC | Number in firmware (no DAC needed) |
| Over-current, OVP | On-chip comparators → COG shutdown | LM2901 quad comparator → FLT pin |
| Boost frequency | 200 kHz | 100 kHz (shared PWM period) |
| Boost inductor L1 | 68 µH | 100 µH, Isat ≥ 3.5 A, DCR ≤ 40 mΩ |
| Boost switch sense | 50 mΩ (in the control loop) | 33 mΩ (protection only) |
| Charger gate driver | UCC27211, separate HI/LI | IR2104: one IN pin, SD pin, fixed dead time about 520 ns, external bootstrap diode |
| Charger dead time | about 50 ns | about 520 ns (inside the IR2104), Schottky D2 across Q4 required |
| Gate-drive supply | 10 V LDO | Battery through 10 Ω / 10 µF (VDRV, 11.2–14.6 V) |
| 5 V supply | Low-Iq LDO | L78L05 (about 3–6 mA quiescent) |
| Fault thresholds | From the 5 V rail | From an LM4040-2.5 reference |
| Charger control | Firmware duty, P&O | Same, plus switching stop below 0.2 A |

Everything else in `DESIGN.md` (LEDs, battery, panel, charger FETs and
inductor, ideal diode, battery protection, layout) carries over unchanged.

## 3. How the LED driver works without analog peripherals

The boost runs in voltage mode, controlled by firmware:

1. A timer interrupt at 10 kHz reads LED current (INA181 → ADC), runs a PI controller using the hardware multiplier, and produces a duty value with fractional bits.
2. One PWM count at 100 kHz moves the output by about 314 mV, which is about 52 mA of LED current (12-LED string, about 6 Ω dynamic resistance). That is too coarse on its own.
3. The PWM overflow interrupt (100 kHz) does sigma-delta dithering: each period it adds the fractional part to an accumulator and writes either N or N+1 counts. With 4 fractional bits the effective step is about 3.3 mA; with 6 bits about 0.8 mA.
4. The dither pattern repeats at 6.25 kHz or faster. The output LC filter (100 µH with 18.8 µF, double pole about 1.3 kHz) smooths it, so the LEDs see nearly DC.
5. Crossover is set to 100–200 Hz, well below the LC double pole and the right-half-plane zero (about 10 kHz at 11.2 V with 100 µH). Brightness changes are ramped over 2 s anyway, so a slow loop is fine.
6. Each loop pass also clamps the duty to D_max = 1 − Vbat / 45 V so the boost cannot push the output far past the LED voltage, even before the OVP comparator trips.

Write both duty bytes right after the PWM overflow interrupt so the
period-end reload never picks up half a value.

CPU load (estimate, measure it with a GPIO toggle on a scope): the
100 kHz dither ISR takes about 30–50 of the 320 CPU cycles per period
(10–15 %), and the 10 kHz PI loop with ADC read about 5–8 %. The rest
is free for MPPT, scheduling and SOC.

If firmware-only control turns out too slow or noisy on the bench, the
fallback is an external analog loop: a small op-amp error amplifier with
a filtered-PWM reference driving the boost duty. That costs one op-amp
and does not change the power stage.

## 4. Charger with the IR2104

The IR2104 has one PWM input (IN) and a shutdown input (SD). With SD high,
IN high turns Q3 on and IN low turns Q4 on, with about 520 ns of dead time
inserted inside the IR2104 at each change. SD low turns both FETs off.

| Item | How |
|---|---|
| IN | PWM0 (pin 28), independent mode, 100 kHz, 10k pull-down |
| SD | P0.1 (pin 27) as a GPIO output, 10k pull-down, so a FLT fault (pins go high-Z) turns both FETs off |
| Supply | VCC from VDRV = battery through R47 10 Ω / C49 10 µF. The IR2104 needs 10–20 V and its undervoltage lockout is about 8–9.8 V, so a 10 V rail would be too close |
| Bootstrap | D16 ultrafast diode (ES1D, 200 V 1 A) from VDRV to VB, C36 100 nF from VB to SW_C |
| Duty | The dead time comes out of the high-side on-time: Q3 conducts for about (IN duty × 10 µs) − 520 ns. Firmware adds 5.2 % to the duty it writes. At a hot panel (Vmp about 15.5 V) the IN duty is about 0.93, leaving Q4 on for about 190 ns per cycle. The bootstrap also charges during the dead time while D2 conducts |
| Low light | The IR2104 cannot hold Q4 off while Q3 switches, so the asynchronous low-current mode is gone. Below about 0.2 A of charge current (80 ADC counts), firmware pulls SD low and stops switching, then retries every 5 s. The LM74700 ideal diode still blocks current from flowing back into the panel; without the stop, the converter would only circulate inductor ripple current and waste about 0.3 W |

Estimated charger efficiency with the IR2104 (using its minimum drive
current, 130/270 mA): 97.4 % at 80 W, 97.4 % at 40 W, 96.1 % at 16 W.
The extra loss against the UCC27211 is about 0.6 W of slower switching
and 0.27 W in D2 during the longer dead time. With the typical drive
current (210/360 mA in the KiCad symbol description) the switching loss
is about a third lower.

## 5. Protection with one FLT pin

LM2901 quad open-collector comparator. All four outputs wired-OR to FLT
(P0.4) with a 4.7 kΩ pull-up to 5 V. FLT set active low, latched mode,
1 µs filter. Thresholds come from dividers on VREF25, a 2.500 V LM4040
reference fed from 5 V through 3.0 kΩ. The L78L05 is only ±5 %: with the
dividers on the 5 V rail the battery over-voltage trip could fall to
14.24 V, below the 14.4 V charge voltage.

| Comparator | Input | Trip point |
|---|---|---|
| A | Boost switch current, 33 mΩ in Q1 source, 100 Ω / 1 nF filter | 21.0k / 1.0k from 2.5 V → 0.114 V = 3.4 A |
| B | LED output voltage, R5/R6 430k / 20k (also the ADC reading) | 3.01k / 10k → 1.92 V = 43.2 V |
| C | Charger current, U5 INA181A3 output | 8.06k / 10k → 1.38 V = 6.9 A |
| D | Battery voltage, R3/R4 91k / 10k | 6.81k / 10k → 1.49 V = 15.0 V (about 14.7–15.3 V with 1 % parts) |

The dividers draw 0.59 mA from VREF25; R48 supplies 0.83 mA at 5.0 V, which
leaves about 0.24 mA for the LM4040 (0.16 mA at 4.75 V, 0.32 mA at 5.25 V).

A fault stops all PWM outputs at once. That is acceptable here because
the charger only runs by day and the LED driver only by night, so one
shared fault input never shuts down a converter that should keep going.
Firmware reads the ADC to find which fault fired, logs it, clears
FLTSTA1 after 1 s and retries, up to 5 times.

Because the PWM pins go high impedance on a fault, fit 10 kΩ pull-downs
on the IR2104 IN and SD inputs and on the boost driver input. SD low turns
both charger FETs off.

## 6. Pin assignment (28-pin SOP/TSSOP)

| Pin | Port | Function in this design |
|---|---|---|
| 28 | P0.0 / PWM0 | Charger PWM → IR2104 IN |
| 27 | P0.1 | Charger enable → IR2104 SD (GPIO; low = both FETs off) |
| 26 | P0.2 / PWM2 | Boost Q1 → UCC27511 IN+ |
| 25 | P0.3 / PWM3 | Unused |
| 24 | P0.4 / FLT | Wired-OR fault input from LM2901 |
| 18 | P2.2 / AIN0 | Panel voltage divider |
| 17 | P2.3 / AIN1 | Battery voltage divider |
| 16 | P2.4 / AIN2 | Charger current (INA181 #1) |
| 15 | P2.5 / AIN3 | LED current (INA181 #2) |
| 14 | P2.6 / AIN4 | LED voltage divider |
| 13 | P2.7 / AIN5 | Battery NTC |
| 12 | P1.7 / AIN6 | LED board NTC |
| 11 | P1.6 / AIN7 | Spare ADC input |
| 10 | P1.5 | LED disconnect FET Q2 gate |
| 9 | P1.4 | PIR / motion sensor input (optional) |
| 23 | P0.5 | Spare |
| 20, 19 | P2.0 / P2.1 | UART (USCI0) for service and logging |
| 7, 8 | P1.2 / P1.3 | Programming and debug (tCK / tDIO) |

PWM4–PWM7 share pins with AIN2–AIN5, so those pins are used as ADC
inputs and those PWM channels stay off.

## 7. Efficiency (estimates)

| Path | Estimate |
|---|---|
| Battery → LED (UCC27511 + D1), 11.2 / 12.8 / 14.4 V | 95.8 / 96.0 / 96.2 % |
| Battery → LED at 50 % / 30 % brightness | 95.1 / 93.5 % |
| Panel → battery (IR2104), 80 / 40 / 16 W | 97.4 / 97.4 / 96.1 % |
| Panel → LED including the battery cycle | 88.9 % |

Each converter stays above 91 %. Against the UCC27211 / LM2936 parts the
LED driver loses about 0.4 points (L78L05 quiescent current and gate drive
at battery voltage) and the charger about 1 point (IR2104 edges and dead
time). The L78L05 costs about 1.4 Wh a day; autonomy stays at about 2.4
nights.

End to end, the estimate is now about 89 %. A synchronous boost no longer
helps: driven by a second IR2104 it comes out at 95.3 %, below the
asynchronous boost, because the slow edges and 520 ns dead time cost more
than D1 does. If 91 % has to hold end to end, the charger needs a fast
driver with short dead time again (UCC27211 or similar) and the boost a
synchronous FET with a fast driver.

## 8. Extra parts compared with the PIC design

| Part | Qty | Purpose |
|---|---|---|
| INA181A1 | 1 | LED current sense (U6) |
| INA181A3 | 1 | Charge current sense (U5), replaces the gain-50 part |
| LM2901 quad comparator | 1 | Hardware fault detection into FLT |
| 32.768 kHz crystal + 2 caps | 1 | Night timing, HRC calibration |
| 10 kΩ pull-downs | 3–4 | Gate-driver inputs stay low when PWM goes high-Z |
| Schottky D2 across Q4 | 1 | Required (520 ns dead time in the IR2104) |
| LM4040-2.5 + 3.0k + 100 nF | 1 | Reference for the fault thresholds |
| ES1D (D16) + 100 nF | 1 | IR2104 bootstrap supply |

Parts in the KiCad project:

| Function | Part | Notes |
|---|---|---|
| Charger gate driver | IR2104 (SOIC-8) | 600 V, single IN + SD, fixed dead time about 520 ns, VCC 10–20 V |
| Boost gate driver | UCC27511 (SOT-23-6) | Split outputs: 4.7 Ω turn-on, 2.2 Ω turn-off |
| Gate-drive supply | Battery through 10 Ω / 10 µF (VDRV) | No regulator |
| 5 V logic rail | L78L05 (LM78L05), SOT-89 | 30 V input, about 1.7 V dropout, 3–6 mA quiescent, ±5 % |
| Fault reference | LM4040-2.5 (SOT-23) | 2.500 V shunt reference |
| Bootstrap | ES1D + 100 nF | Ultrafast, 200 V |
| Panel TVS | SMBJ28CA (bidirectional) | Also takes reverse surges on the panel cable |

The NTC dividers run from the 5 V rail, so their readings move with the
L78L05's ±5 %, about ±3 °C near the 0 °C charge cutoff. Firmware measures
VDD through the internal 1/4 VDD ADC channel and scales the NTC readings.

## 9. Things to verify on the bench

1. IR2104 dead time and switching edges on the real Q3/Q4 (scope HO−VS and LO), and the Q3 on-time at the highest duty. Check the IR2104 datasheet values used here: 130/270 mA drive, about 520 ns dead time, 8–9.8 V UVLO.
2. FLT response time from comparator edge to PWM pins going high-Z.
3. LED current ripple from the dither, measured with a current probe. Aim for under 5 % peak to peak.
4. PI loop step response to a brightness change and to a battery voltage step, at 11.2, 12.8 and 14.4 V.
5. CPU load of the two interrupts.
6. Charger behaviour at dawn and dusk: the stop below 0.2 A and the 5 s retry.
7. Efficiency, using the procedure in `DESIGN.md` section 13, with the SC95F8523, INA181s, LM2901, LM4040 and L78L05 supply current counted in the input.
